Video Production Pipeline

AI-конвейер коротких вертикальных роликов (1080×1920) для game-каналов. Сценарий, голос, изображение, видео, монтаж — всё через сабагенты Claude поверх fal.ai, MiniMax, Kling, FFmpeg и Supabase.

Стек: Claude Code (Sonnet/Haiku) · fal.ai (MiniMax, Kling, NB2, Chatterbox) · Supabase · FFmpeg Корень: video-agent/ Формат: 1080×1920, 25–60s Стоимость ролика: $1.5–$6

Как пользоваться

Просто описываешь идею человеческим языком — Manager сам детектит игру и формат и ведёт ролик через все фазы.

Запуск

  • Пиши идею в свободной форме: игра (при необходимости — game_tag) + формат (или ключевые слова формата) + сама идея/сюжет. Если формат не назван явно, Manager определяет его по таблице ключевых слов из manager.md и переспрашивает при неоднозначности.
  • Пример: «Сделай serial-drama по star-trek-timelines, продолжение Mirror Kirk arc» или «reddit-story про marvel snap — история про неудачный пул карт».
  • Для новой серии/формата, у которого ещё нет story bible, Manager остановится и спросит подтверждение перед созданием — сам не создаёт молча.

Что происходит дальше

  • Manager последовательно вызывает 5 сабагентов (Scenarist → Sound → Storyboarder → Animator → Editor), после каждой фазы — только программная проверка (filesize/ffprobe/jq), без визуального просмотра PNG/MP4.
  • Review gate (обязателен всегда): после Editor тебе показывают локальный final.mp4 и ждут явного «ок». Без этого шага ничего не публикуется и не коммитится.
  • После твоего «ок»: загрузка в Supabase → отложенная публикация на YouTube → запись в лог → обновление точной story bible → git push.
  • TikTok/Instagram публикуются только по отдельной явной команде («опубликовать в тик-ток starfleet») — автоматически не постятся.

Debug mode

  • Добавь в запрос фразу Debug mode / «Отладочный режим» — Manager останавливается после каждой фазы (включая Phase 0) и присылает промежуточный результат на подтверждение, не пропуская и не переставляя фазы.

Важно знать

  • Твоя живая команда всегда важнее правил формата. Если явно просишь «без спидапа» или «голос X» — применяется без исключений, даже если формат по умолчанию говорит иначе.
  • Средняя стоимость ролика — $1.5–$6, самая дорогая фаза — Kling (Animator).

Поток файла storyboard.json

Один JSON растёт через все 4 фазы: каждый агент дописывает свои поля, не удаляя чужие.

Scenarist     →  scenes[].narrative_text, action_description, facial_expression,
                 character_state, visual_identity, voices, duration_sec, clip_type

Sound         +  scenes[].tts_url       (Supabase public URL .mp3)
              +  scenes[].tts_dur       (ffprobe seconds)
              +  bg_music_url

Storyboarder  +  scenes[].image_prompt  (для NB2)
              +  scenes[].scene_image_url   (Supabase public URL .png)

Animator      +  scenes[].motion_prompt (для Kling)
              +  scenes[].clip_url      (локальный путь .mp4)
              +  cost_log[]

Editor        →  читает всё, пишет final.mp4 на диск + загружает в Supabase

Sub-agents — пять ролей

Manager parent

Оркестратор. НЕ пишет storyboard, НЕ зовёт fal.ai, НЕ запускает ffmpeg. Только Agent-вызовы + git + детект формата + cost report.

Что делает

  • git pull origin main в самом начале
  • Детект формата из user request → читает rules/formats/{format}.md
  • Делегирует 5 фаз через Agent tool
  • Программатическая валидация после каждой фазы (filesize, ffprobe — без визуальной читки PNG/MP4)
  • Обновляет story bible (для serial-drama / reddit-story)
  • Финальный cost report + git push

rules/roles/manager.md

Scenarist sonnet

Пишет storyboard.json (narrative side). Никаких изображений, видео, аудио.

Что делает

  • Сцены/биты, action_description, dialogue
  • visual_identity, facial_expression, character_state
  • Согласует длительности с budget'ом формата
  • Для серий — читает story bible, дописывает её

rules/roles/scenarist.md · prompts/scenarist.txt

Sound haiku

Routed TTS только там, где нужна внешняя речь. Загрузка MP3 в Supabase, URL'ы обратно в storyboard.json. Генерация bg-music.

Что делает

  • Выбор движка: native audio (Kling I2V voice_ids, напр. serial-drama dialogue) → exact-format approved Chatterbox voice-clone sample → иначе MiniMax Speech 2.8 HD
  • Voice mapping из game config / story bible (один персонаж = один голос на весь сериал)
  • Загрузка MP3 в Supabase Storage, public URL
  • Генерация bg-music через MiniMax Music (fal-ai/minimax-music/v2.6) — обязательна для serial-drama и dual-style-v3, локальная music/-библиотека больше не используется как источник
  • Для длинных монологов (>80 слов) — обязательная резка на чанки ≤35 слов (Chatterbox тихо ломается на длинном тексте)

rules/roles/sound.md · prompts/sound.txt

Storyboarder sonnet

Переводит action_description в image_prompt, генерит PNG через Nano Banana 2, грузит в Supabase. Chain-ref для consistency.

Что делает

  • Решает камеру, угол, оптику, гэйз персонажей
  • Chain-ref: scene-N = [character-sheet, scene-(N-1)] для continuity
  • NB2 prompt-engineering (без негаций, photographic vocabulary)
  • Для Avatar-сцен — zero-text rule (никакого текста в кадре, иначе Kling превратит в иероглифы)
  • Программатическая валидация PNG: filesize, dimensions, ffprobe

rules/roles/storyboarder.md · prompts/storyboarder.txt

Animator sonnet

Kling I2V (action) или Kling Avatar v2 (dialogue/lipsync). Самая дорогая фаза — $0.28–$1.40 за вызов.

Что делает

  • Пишет motion_prompt сам, из action_description + facial_expression
  • I2V: v3 Standard ($0.084/s) — primary; v2.6 Pro — fallback
  • Avatar: Kling Avatar v2 Standard ($0.056/s), hard cap 25s TTS
  • Multi-prompt для длинных action-сцен (до 15s, 6 shots)
  • Программатическая валидация MP4: filesize, ffprobe duration, video/audio streams

rules/roles/animator.md · prompts/animator.txt

Editor sonnet

FFmpeg-сборка final.mp4. Нормализация, concat, субтитры, музыка, CTA, загрузка в Supabase. Никаких AI-API.

Что делает

  • Trim каждого клипа (Avatar tail = TTS_dur + 0.3s)
  • concat через -f concat, нормализация SAR/FPS
  • Субтитры: add_subtitles.py (faster-whisper → ASS chunks по 3 слова)
  • Audio mix: voice 100%, bg-music ~20%, gameplay 25% (где есть)
  • Speedup (для gameplay-ai-avatar — 1.3×)
  • Upload final.mp4 в Supabase

rules/roles/editor.md · prompts/editor.txt

Publisher main session

Два флоу: (1) YouTube — приватная загрузка с отложенной датой после генерации; (2) TikTok/Instagram — post-now через mobile-mcp (Android по USB).

YouTube (основной флоу)

  • Запускается после генерации — спрашивает сколько роликов загрузить
  • Смотрит последнюю запланированную дату из video_agent_runs.yt_published и ставит следующий ролик на day+1 в 20:59 UTC (23:59 МСК)
  • Загружает как private + publishAt через youtube-upload.sh
  • Записывает дату в yt_published через log-publish.sh --platform yt

TikTok / Instagram (post-now)

  • Триггер — явная команда: «опубликовать в тик-ток starfleet»
  • fetch-for-publish.sh скачивает ролик из Supabase, кладёт через adb
  • mobile-mcp открывает приложение, выбирает аккаунт и видео

Внешние сервисы

fal.ai

Прокси к моделям. Пять семейств: NB2 (картинки), Kling (видео + avatar lipsync), MiniMax (TTS + music), Chatterbox (voice-clone TTS), ElevenLabs (только sound-effects).

Эндпоинты в работе

  • fal-ai/nano-banana-2/edit — text-to-image + chain-ref edit (primary)
  • fal-ai/gpt-image-1/text-to-image — alternate, user-only
  • fal-ai/kling-video/v3/standard/image-to-video — I2V primary
  • fal-ai/kling-video/v2.6/pro/image-to-video — I2V alternate, user-only
  • fal-ai/kling-video/ai-avatar/v2/standard — Avatar lipsync
  • fal-ai/kling-video/v3/standard|pro/motion-control — motion transfer (motion-dance)
  • fal-ai/minimax/speech-2.8-hd — TTS, default route
  • fal-ai/minimax-music/v2.6 — bg-music generation
  • fal-ai/chatterbox/text-to-speech — voice-clone TTS (only exact-format/series approved sample)
  • fal-ai/elevenlabs/sound-effects — SFX only, ElevenLabs TTS itself is forbidden

Async очередь. fal.ai temp-URLs живут часами — поэтому всё перезаливаем в Supabase до Kling-вызова.

Supabase

Постоянное хранилище всех ассетов + БД с метаданными.

Storage (через queue/upload-asset.sh)

  • assets/{game}/characters/{slug}/{sheet,avatar,variants/*}.png — реестровые рефы, шарятся между эпизодами
  • assets/{game}/locations/{slug}.png, assets/{game}/branding/{cta,opener,...}, assets/{game}/gameplay/*.mp4
  • episodes/{game}/{date}-{format}/scenes/{file} — per-episode scene PNG/MP4, не регистрируются в БД
  • episodes/{game}/{date}-{format}/tts/{file} — per-episode TTS MP3, не регистрируются в БД

DB

  • game_assets — реестр ассетов (URL, tags, prompt_block)
  • video_tasks — очередь для worker'а (queue mode)

MiniMax / Chatterbox

Два TTS-бэкенда через fal.ai, выбор по приоритету (§1 sound.md): native audio (напр. serial-drama Kling I2V) → Chatterbox, только если у точного формата/серии есть approved voice sample → иначе MiniMax Speech 2.8 HD (default для всего, включая Star Trek serial-drama). Voice sample не переносится между форматами без явного user override.

Голоса

  • Voice mapping в sound.md + per-game в game config / story bible (locked per character на весь сериал)
  • MiniMax: preset voices (Deep_Voice_Man, Determined_Man, Calm_Woman и т.д.), emotion + speed
  • Chatterbox: voice-clone из reference MP3, JSON-тело пишется через Python (не bash heredoc — апострофы убивают аудио)

FFmpeg

Локально, версия с libass (для ASS-субтитров). Никаких облаков.

Используется

  • Editor: concat, trim, atempo, amix, drawbox, subtitles burn-in
  • Animator: ffprobe (validation), bridge-frame extraction (multi-call chain)
  • Sound: ffprobe duration
  • Бинарь: /usr/local/bin/ffmpeg-full/ffmpeg (libass-enabled)

Принципы

  • Manager не делает работу sub-agent'ов. Если делает — всё едет на дорогую parent-модель, стоимость x3.
  • Не читай PNG/MP4 визуально. Валидация — только программатическая (filesize + ffprobe). Качество — на уровне промпта, не на инспекции глазами.
  • Никогда не из памяти — всегда читай rule-файлы. Правила меняются.
  • Перед дорогим вызовом — Supabase upload. fal.ai temp-URLs протухают, Kling за $1.40 не успеет скачать.
  • storyboard.json — единственный канал между фазами. Sub-agent'ы не видят чужой контекст.
  • Debug mode — остановка после каждой фазы для confirm.
